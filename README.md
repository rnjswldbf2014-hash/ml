# dplayg

D 언어로 구현한 RL/SL 라이브러리(`ml`) 프로젝트입니다.
`ml.d`를 빌드하면 파이썬 확장 모듈인 `ml.pyd`가 생성되며, 파이썬에서 사용할 수 있습니다.

---

## 한 장 요약

```python
from ml import make, cos, vec, attn, each, conv, memory, logic, jepa

ai = make("이름", [입력수, 은닉...], 출력)      # 외울 건 이 셋뿐
```

**은닉 자리에 넣는 것** (안 쓰면 그냥 정수)

| | 뭐냐 |
|---|---|
| `128` | 보통 층 |
| `attn(조각수)` | 항목끼리 서로 참조 |
| `each(폭)` | 항목마다 따로 가공 (가중치 공유) |
| `conv(채널, 창)` | 창을 미끄러뜨리며 같은 무늬 찾기 |
| `memory(칸수)` | 과거를 기억 (판을 `with ai.round():` 로 감쌈) |
| `logic(게이트수)` | 논리 게이트 — `ai.rules()` 로 읽을 수 있음 |

**출력 자리** — 하나면 감싸지 않아도 됩니다

| | 뭐냐 |
|---|---|
| `["A","B"]` | 고르기 |
| `cos` | 숫자 하나 |
| `vec(n)` | 숫자 n개 (`jepa` 용, `ai.embed()` 로 꺼냄) |
| `[["A","B"], cos]` | 출력 두 개 |

**부르는 것**

```python
step   = ai.rl(관측)            # 골라보기 (모델 안 바뀜)
ai.save(ai.reward(step, 점수))  # 배우기
ai.sl(입력, 정답)                # 정답을 알 때
ai.predict(관측)                 # 안 배우고 최선만
```

**나중에 바꿀 수 있는 것** — `make()` 에 넣어도 되고 나중에 바꿔도 됩니다

```python
ai.lr = 0.02       # 학습률 (안 배워지면 제일 먼저 만져볼 값)
ai.decay = 0.001   # 과적합 막기 (기본 0 = 끔)
ai.temp = 0.3      # 고르기 과감함 (0 = 최선만)
ai.autosave = 100  # 몇 번에 한 번 파일로 쓸지
ai.sigma, ai.entropy = 1.0, 0.01
```

**출력이 여러 개면** 반환·보상·정답·legal 도 그 개수만큼의 리스트입니다
(`None` 을 주면 그 출력은 학습에서 빠집니다). 하나일 때는 그냥 값으로 줘도 됩니다.

## 설계 원칙

이 라이브러리의 함수는 **데이터를 만드는 함수** 와 **모델을 바꾸는 함수** 로 나뉩니다.

| 함수 | 순수? | 하는 일 |
|---|---|---|
| `rl()` | 순수 | `(입력, 출력)` 데이터만 만듭니다. 가중치를 건드리지 않습니다. |
| `reward()` | 순수 | `(입력, 출력, 보상)` 데이터만 만듭니다. |
| `episode()` | 순수 | 여러 스텝에 같은 보상을 매깁니다. |
| `predict()` | 순수 | 샘플링 없이 최선의 값만 봅니다. |
| **`save()`** | **아님** | **역전파 + 파일 저장. 모델이 바뀌는 유일한 곳입니다.** |

`rl()` 을 몇 번을 부르든 모델은 그대로입니다. 학습은 `save()` 를 부를 때만 일어납니다.

## 출력은 항상 리스트

출력이 하나든 여럿이든 **모양이 같습니다.** 출력 개수를 바꿔도 코드가 안 깨집니다.

```python
import ml

ai = ml.make("M", [12, 128], [["왼쪽", "오른쪽"]])       # 하나여도 감쌈

step = ai.rl(입력)
행동 = step.output[0]                                 # 항상 [0]

ai.save(ai.reward(step, [1.0]))                       # 점수도 리스트
ai.sl(입력, ["왼쪽"])                                  # 정답도 리스트
ai.rl(입력, legal=[["왼쪽"]])                          # legal 도 리스트
```

출력을 늘리면 자리만 늘어납니다.

```python
ai = make("M", [12, 128], [["왼쪽", "오른쪽"], cos])

행동, 파워 = ai.rl(입력).output
ai.save(ai.reward(step, [1.0, None]))                 # None = 그 출력은 학습 제외
ai.sl(입력, ["왼쪽", 2.5])
```

## 모델 만들기

```python
from ml import make, cos

ai = make("MyModel", [12, 128, 128], [["왼쪽", "오른쪽", "정지"]])
```

| 인자 | 설명 |
|---|---|
| 1번째 | 모델 이름. 가중치 파일명(`이름_ml_memory.pth`)에 씁니다. |
| 2번째 | 레이어 구조 `[입력수, 은닉...]`. 은닉층은 몇 개든 됩니다. 출력은 여기 안 씁니다. `attn(n)` 을 끼우면 어텐션 층이 됩니다. |
| 3번째 | 출력 스펙. **항상 리스트**입니다. 하나여도 `[["A","B"]]` 처럼 감쌉니다. |
| `optimizer` | `'adam'`(기본) / `'sgd'` / `'rmsprop'` / `'adagrad'` |
| `lr` | **학습률** — 틀렸을 때 얼마나 크게 고칠지 (기본 0.01) |
| `decay` | **가중치 감쇠** — 외우기(과적합)를 막는 힘 (기본 0 = 끔) |
| `temp` | **고르기 온도** — 얼마나 과감하게 고를지 (기본 1.0, 0 이면 최선만) |
| `sigma` | cos 가 값을 얼마나 넓게 탐험할지 (기본 1.0) |
| `entropy` | 고르는 쪽이 한 가지 답으로 굳는 것을 막는 힘 (기본 0.01) |

`lr`, `decay`, `temp`, `sigma`, `entropy` 는 **만든 뒤에도 바꿀 수 있습니다.**
학습률을 점점 줄이거나, 탐험을 점점 줄이는 데 씁니다.

```python
ai = make("M", [12, 128], 출력, lr=0.02)

for i in range(에폭수):
    ai.lr = 0.02 * (1 - i / 에폭수)      # 갈수록 조심스럽게
    ai.temp = max(0.1, 1.0 - i / 에폭수)  # 갈수록 덜 모험적으로
    ...
```

- **`lr` 이 안 배워질 때 제일 먼저 만져볼 값입니다.** 크면 요동치고 작으면 느립니다.
- `decay` 는 학습 데이터를 통째로 외워버리는 것을 막습니다. `1e-4` ~ `1e-2` 부터
  시작해보세요. 편향과 `logic` 게이트에는 걸리지 않습니다.
- `temp` 는 `predict()` 에는 영향이 없습니다 (거긴 원래 샘플링을 안 합니다).

같은 이름의 파일이 있으면 이어서 학습합니다.
단, 저장된 구조가 요청한 `layers` 와 다르면 파일을 무시하고 새로 만듭니다.

## 강화학습

```python
step   = ai.rl([0.1, 0.2, ...])        # → Step(input, output)
scored = ai.reward(step, +1.0)         # → Scored(input, output, point)
ai.save(scored)                        # 학습 + 저장
```

`step.input` / `step.output` 으로 꺼내 쓰고, 언패킹도 됩니다.

```python
입력, 출력 = ai.rl([0.5])
```

### 묶어서 학습 (권장)

한 번에 여러 스텝을 넘기면 그만큼 빨라집니다.

```python
batch = []
for i in range(32):
    step = ai.rl([i / 32])
    point = +1.0 if step.output == "왼쪽" else -1.0
    batch.append(ai.reward(step, point))
ai.save(batch)
```

### 에피소드 단위 보상

게임이 끝난 뒤 결과를 알 때 씁니다.

```python
steps = [ai.rl(상태) for 상태 in 게임진행()]
ai.save(ai.episode(steps, +1.0 if 이겼으면 else -1.0))
```

### 고를 수 있는 것이 제한될 때

```python
step = ai.rl(상태, legal=["왼쪽", "정지"])   # 이 중에서만 고릅니다
```

## 숫자 출력 (cos)

고를 이름 대신 `cos` 를 넘기면 실수를 반환합니다.

```python
ai = make("NumModel", [2, 64], [cos])

step = ai.rl([0.5, 0.5])
print(step.output[0])                    # 예: 1.63

오차 = abs(step.output[0] - 3.0)
ai.save(ai.reward(step, [1.0 - 오차]))   # 3 에 가까울수록 높은 점수
```

값은 **0 근처에서 시작합니다.** 원하는 범위가 따로 있으면 쓰는 쪽에서 펼쳐 쓰세요.

```python
파워 = 20 + step.output[0] * 10   # 출력 -1~1 → 파워 10~30
```

## 출력 여러 개

레이어 마지막을 리스트로 주면 출력이 여러 갈래가 됩니다.
출력끼리 몸통 신경망을 공유합니다.

```python
ai = make("Game", [38, 128, 128],
          [["점프", "왼쪽", "오른쪽", "정지"], cos])

step = ai.rl(상태)
행동, 파워 = step.output          # ('왼쪽', 27.3)
```

고르기와 `cos` 를 자유롭게 섞을 수 있고, 개수 제한도 없습니다.

```python
make("M", [입력, 은닉, 은닉], [cos, cos, ["안녕", "친구들"], ["영어", "한국어"]])
```

### 출력마다 다른 보상

```python
ai.save(ai.reward(step, [행동점수, 파워점수]))
```

`None` 을 주면 그 출력은 이번 학습에서 빠집니다.
점프를 안 한 순간에 점프 파워를 학습시키면 안 되니까요.

```python
ai.save(ai.reward(step, [점수, 점수 if 점프했나 else None]))
```

### 출력마다 고를 수 있는 것 제한

```python
ai.rl(상태, legal=[["왼쪽", "정지"], None])
```

## 어텐션 층

은닉층 자리에 `attn(항목수)` 를 넣으면, 그 층에서 **항목끼리 서로 참조**합니다.

```python
from ml import make, attn, each

ai = make("M", [12, attn(6), each(24), attn(6), each(24), 128], [["A", "B"]])
```

`attn(6)` 은 들어온 폭을 6조각으로 나눠, 어느 조각을 볼지 스스로 정합니다.
폭은 그대로 나옵니다.

## each — 항목마다 따로 도는 층

`attn` 은 항목끼리 섞기만 하고 가공은 못 합니다. 그 가공을 하는 것이 `each` 입니다.

```python
each(24)     # 항목 하나를 24칸으로. 가중치는 하나를 모든 항목이 나눠 씀
```

**일반 층을 쓰면 안 됩니다.** 일반 층은 전체를 한 덩어리로 섞어서 항목 구분이
사라집니다. `attn` 이 만들어둔 정보가 거기서 없어집니다.

| 층 | 하는 일 |
|---|---|
| `attn(n)` | 항목끼리 서로 참조 (가로로 섞음) |
| `each(폭)` | 항목마다 따로 가공, 가중치 공유 (세로로 처리) |
| 일반 층 | 전부 합침 — 항목 구분 끝 |

보통 `attn` 과 `each` 를 번갈아 쌓고, 마지막에 일반 층으로 합칩니다.

### 실제 차이

항목 6개 중 **값이 가장 큰 것의 태그**를 맞히는 문제입니다. 순서가 매번 바뀌어서
"몇 번째 자리"로는 못 풉니다.

| | 정확도 |
|---|---|
| 일반 층만 | 87.8% |
| `attn` 만 | 87.5% |
| `attn` + `each` | **98.8%** |

`attn` 만 넣으면 소용이 없고, `each` 와 같이 써야 효과가 납니다.

### 파라미터도 훨씬 적습니다

| | 개수 |
|---|---|
| 일반 층 128→256 | 32,768 |
| `each(32)` (항목 8개 공유) | 512 |

### 언제 쓰나

입력에 **같은 종류가 여러 개** 있고, 그 중 뭐가 중요한지가 상황마다 바뀔 때입니다.
적 여러 명, 아이템 목록, 맵 칸 같은 경우요.

그냥 서로 다른 값들(체력, 속도, 거리)뿐이면 효과가 없고 계산만 늘어납니다.

**비용** — 항목 수의 제곱에 비례합니다.

`each` 는 앞에 `tok` 이나 `attn` 이 있어야 항목 수를 알 수 있습니다.

## 번호를 입력으로 줄 때

글자, 직업, 아이템 종류처럼 **크기에 뜻이 없는 번호**는 그대로 넣으면 안 됩니다.
신경망이 5를 10의 절반으로 보기 때문입니다.

번호마다 자리를 하나씩 만들고, 자기 자리만 1로 켜서 넣습니다 (one-hot).

```python
def 켜기(번호, 종류수):
    v = [0.0] * 종류수
    v[번호] = 1.0
    return v

ai = make("M", [33, 128, 128], [답목록])
ai.sl(켜기(5, 33), ["정답"])
```

여러 개면 이어붙입니다.

```python
ai = make("M", [16*33, 256], [글자목록])          # 글자 16개
ai.sl(켜기(a,33) + 켜기(b,33) + ..., ["정답"])
```

번호를 그대로 넣는 것과 차이가 큽니다. 번호 33개에 답이 무작위로 붙은 문제에서:

| | 정확도 |
|---|---|
| 번호 그대로 | 55% |
| 0~1 로 정규화 | 58% |
| one-hot | **100%** |

## 묶음 학습

`sl()` 에 여러 개를 겹쳐 주면 한 번에 처리합니다. **훨씬 빠릅니다.**

```python
ai.sl(입력, 정답)                                   # 하나씩
ai.sl([입력1, 입력2, ...], [정답1, 정답2, ...])      # 묶음
```

하나씩 부르면 문제마다 가중치 전체를 갱신합니다. 파라미터가 20만 개면
순전파보다 그 갱신이 더 비쌉니다. 묶음으로 주면 기울기를 모았다가 **한 번만**
갱신합니다.

| 32,000문제 | 시간 | 정확도 |
|---|---|---|
| 하나씩 | 143초 | 21% |
| 묶음 32 | 12초 | 84% |

묶음 크기는 직접 정합니다. 크게 잡으면 빠르지만 갱신 횟수가 줄어듭니다.

## 지도학습

정답을 알고 있을 때 씁니다.

```python
ai.sl([0.1, 0.2, 0.3], ["왼쪽"])  # 정답을 주면 학습하고 예측을 반환
ai.sl([0.1, 0.2, 0.3])           # 정답이 없으면 예측만
```

출력이 여러 개면 정답도 하나씩 줍니다. `None` 은 건너뜁니다.

```python
ai.sl(상태, ["점프", 1.0])        # 첫 출력 정답, 둘째 출력 목표값
ai.sl(상태, ["왼쪽", None])       # 둘째 출력은 학습 안 함
```

## 예측만 하기

학습도 샘플링도 없이, 가장 점수가 높은 것을 반환합니다.

```python
ai.predict([0.1, 0.2, 0.3])
```

## conv — 창을 미끄러뜨리며 무늬 찾기 (합성곱)

같은 종류의 무늬가 **어디에 있든** 알아봐야 할 때 씁니다. 소리, 센서 기록, 글자 줄,
시간에 따라 변하는 값 — 이미지만의 것이 아닙니다.

작은 창 하나를 쭉 미끄러뜨리면서 같은 무늬를 찾습니다. "왼쪽 끝의 세로선" 과
"오른쪽 끝의 세로선" 을 따로 배우지 않고, **세로선 찾는 법 하나**를 배워서 전체에
돌려 씁니다. 그래서 가중치가 훨씬 적고, 위치가 바뀌어도 통합니다.

```python
from ml import make, conv, each

# 길이 24 짜리 줄 (채널 1개)
ai = make("M", [24, conv(8, 3, 24), each(4), 16], 출력)
#                     ↑채널 ↑창 ↑항목수
```

입력을 **"항목 n개 × 채널 c개"** 로 봅니다. 위 예에서는 항목 24개, 채널 1개죠.
`conv(8, 3, 24)` 는 "창 3칸을 미끄러뜨려 8가지 무늬를 찾아라" 입니다.

### 항목 수를 왜 직접 줘야 하나

입력폭이 24 라고 해서 "항목 24 × 채널 1" 인지 "항목 8 × 채널 3" 인지 알 수 없습니다.
그래서 **맨 앞에 쓸 때는 직접 알려줘야** 합니다.

앞에 `attn` 이나 다른 `conv` 가 있으면 거기서 물려받으니 생략할 수 있습니다.

```python
ai = make("M", [24, attn(6), conv(8, 3), 16], 출력)     # 항목 6개를 물려받음
```

### 알아둘 것

- **길이가 유지됩니다** (출력도 항목 n개, 양끝은 0 으로 메웁니다). 그래서 `attn`,
  `each` 와 섞어 쓸 수 있고 항목 구분도 그대로 넘어갑니다.
- 창 크기는 짝수도 됩니다.
- **1차원만 있습니다.** 2차원(이미지 전용)은 없습니다. 이미지는 한 줄씩 보는
  식으로 쓸 수 있지만, 세로 방향 무늬는 못 잡습니다.
- 여러 겹 쌓을 수 있습니다 (`conv(4,3,24), conv(8,3)`). 쌓으면 창이 넓어지는
  효과가 나서 더 큰 무늬를 봅니다.

## memory — 기억을 들고 다니는 층 (순환신경망)

지금까지의 신경망은 **"지금 보이는 것"만** 봅니다. 1초마다 기억을 잃는 사람이죠.
"이미 스위치를 눌렀나?" 로 행동이 갈리는 상황을 못 풉니다.

`memory` 층은 신경망 안에 **메모장**을 둡니다. 부를 때마다 "이번 입력과 지금 메모를
보고 메모를 어떻게 고칠지" 를 계산합니다. 입력을 늘리지 않고도 과거를 볼 수 있습니다.

```python
from ml import make, memory

ai = make("M", [입력수, memory(32), 64], [["왼쪽", "오른쪽"]])

with ai.round():               # <- 여기가 판의 시작
    for 관측 in 한판():
        step = ai.rl(관측)     # 여기서 메모가 한 칸 나아간다
                               # <- 여기가 판의 끝
```

**들여쓰기가 곧 판의 범위입니다.** 들어갈 때와 나올 때 양쪽에서 메모를 비웁니다.
판이 어디서 시작하고 끝나는지는 쓰는 쪽만 아는 것이라 — 라이브러리는 알 방법이
없습니다 — 감싸는 행위 자체가 그 선언입니다.

나올 때도 비우는 이유: 들어갈 때만 비우면 블록을 나간 뒤에 메모가 남아서, 판 밖에서
부르는 `predict()` 같은 것이 지난 판의 기억을 들고 돕니다. 중간에 예외로 빠져나가도
비웁니다. `ai.forget()` 을 직접 불러도 되지만, 그쪽은 "어디서 부를지" 를 매번
정해야 하고 이쪽은 정할 게 없습니다.

### ⚠ 가장 중요한 것 — **에피소드를 묶음으로 주세요**

같은 층, 같은 문제, 같은 횟수인데 **부르는 모양에 따라 도달 거리가 몇 배 차이납니다.**

```python
# ① 한 스텝씩 — 기울기가 한 스텝밖에 못 거슬러 간다
with ai.round():
    for 관측, 정답 in 한판():
        ai.sl(관측, 정답)

# ② 에피소드를 묶음으로 — 사슬 전체를 거슬러 간다 (BPTT)
with ai.round():
    ai.sl(한판의_입력들, 한판의_정답들)
```

②가 되는 이유는 **묶음이 곧 사슬**이기 때문입니다. 메모는 묶음 안에서 순서대로
이어지니까, 역전파도 그 순서를 거꾸로 되짚어 갈 수 있습니다. ①은 한 번의 호출
안에 사슬이라고 할 게 없어서(샘플 1개) 구조적으로 불가능합니다.

### 실제로 되는지

단서가 **맨 처음에만** 보이고, 그 뒤로는 입력이 전부 똑같고, K 스텝 뒤에 그 단서를
답해야 하는 문제입니다. 지금 입력만 보면 절대 못 풉니다.

| K (단서와 질문 사이 거리) | 4 | 8 | 16 | 32 |
|---|---|---|---|---|
| ① 한 스텝씩 | 9/10 | 1/10 | 0/10 | 0/10 |
| ② 묶음으로 | **10/10** | **10/10** | **5/10** | 1/10 |

(일반 층은 어느 K 에서도 50% = 찍는 수준. 10번 돌려서 푼 횟수)

묶어서 주되 BPTT 를 끄면 ①과 같아집니다 — **이득은 묶음 자체가 아니라 BPTT 가
냅니다.** 비용은 학습 시간 15~25% 증가뿐입니다.

**결과가 양극단으로 갈립니다.** 한 번 돌리면 100% 아니면 찍는 수준이고 중간이
없습니다. 어느 쪽이 될지는 **처음 가중치 운**이 정합니다. 그래서 K=16 은 "반쯤
됩니다". 안 풀리면 한 번 더 돌려보세요.

### 그래도 한계는 있습니다

**K=8 은 확실하고, K=16 은 반반이고, K=32 는 안 됩니다.** 몇십 스텝은 아직 무리고,
이건 측정값이지 추측이 아닙니다.

①이 왜 그렇게 약했는지 재봤습니다. 1스텝 절단이 내놓는 기울기는 진짜 기울기와
**최대 기울기의 60%** 만큼 어긋나 있었습니다. 대안이 아니라 그냥 틀린 값이었던
겁니다. ①이 그래도 K=4 를 풀던 건 학습 덕이 아니라 **메모가 자연히 흐려지는
속도**(매 스텝 절반쯤)가 거기까지는 버텨준 덕이었습니다.

### 쓸 때 알아둘 것

- **판을 `with ai.round():` 로 감싸세요** (또는 판 시작마다 `ai.forget()`).
  안 감싸면 지난 판의 기억을 들고 시작합니다. `round()` 는 들어갈 때와 나올 때
  양쪽에서 비웁니다. 한 번도 안 비우고 학습하면 **경고가
  한 번 나옵니다** (예전엔 조용히 나빠졌습니다). `memory` 층이 없는 모델에 불러도
  아무 일도 안 하니 안전합니다.
- 메모는 **파일에 저장되지 않습니다.** 배운 값이 아니라 "지금 어디까지 왔나" 라는
  현재 상태니까요. 불러오면 빈 메모로 시작합니다.
- **묶음 학습도 됩니다.** 메모는 순서대로 이어져야 하니 이 층만 차례로 돌고, 앞뒤 층은
  그대로 묶여서 돕니다. 묶어서 준 것들은 **이어지는 스텝으로 취급**됩니다 (섞인
  문제들이 아니라). `jepa` 의 요약기로도 쓸 수 있습니다.
- 온라인 RL 처럼 한 스텝씩밖에 줄 수 없는 상황이면 ① 모양이 되고, 그건 어쩔 수
  없습니다. `rl()` 로 모아서 `save([...])` 로 넘기는 것도 **지금은 권하지 않습니다**
  — 그 경로는 학습할 때 판을 다시 순전파하는데, 그 시작 메모가 "판이 끝난 뒤의
  메모" 라서 엉뚱한 데서 출발합니다 (`forget()` 을 끼우면 답이 완전히 바뀝니다).
  memory + RL 조합은 고쳐야 할 것으로 남아 있습니다.

## logic — 논리 게이트를 배우는 층 (뉴로심볼릭)

일반 층은 뭘 배웠는지 들여다볼 수 없습니다. 숫자 수만 개가 있을 뿐이죠.
`logic` 층은 **배운 것을 논리식으로 읽을 수 있습니다.**

유닛 하나하나가 논리 게이트 한 개입니다. 들어온 값 중 **두 칸**을 보고,
그 둘로 뭘 할지를 **16가지 중에서 배웁니다** (AND, OR, XOR, NAND, "그대로",
"항상 참" ...).

```python
from ml import make, logic

ai = make("M", [2, logic(1)], [["0", "1"]])

X = [[-6, -6], [-6, 6], [6, -6], [6, 6]]      # 거짓/참을 큰 음수/양수로
Y = [["0"], ["1"], ["1"], ["0"]]               # XOR
for _ in range(400):
    ai.sl(X, Y)

print(ai.rules())       # -> [['x0⊕x1   (92%)']]
```

**학습해서 XOR 을 찾아냈고, 그걸 말로 돌려줍니다.**

### 어떻게 미분이 되나

"AND냐 OR냐" 는 원래 뚝뚝 끊긴 선택이라 미분이 안 됩니다. 그래서 **섞습니다.**
16가지 게이트에 각각 비중을 두고, 그 비중을 학습합니다.

학습 중에는 "70% AND, 20% OR, 10% 나머지" 같은 애매한 상태로 있다가 한쪽으로
몰립니다. 다 끝나면 제일 큰 것만 읽으면 그게 배운 논리식입니다.
괄호 안 숫자가 **확신도**입니다 — 낮으면 아직 안 굳은 것이니 더 학습시키거나
그 유닛은 무시하세요.

참/거짓 대신 0~1 사이 값을 쓰고, 게이트도 그에 맞게 늘려 씁니다
(`a∧b` → `a·b`, `a∨b` → `a+b-ab`, `¬a` → `1-a`). 입력이 딱 0/1 이면 보통 논리와
똑같아집니다.

### 실제로 되는지

| 문제 | 정확도 | 배운 논리식 |
|---|---|---|
| XOR | 4/4 | `x0↔x1` (92%) |
| AND | 4/4 | `x0∧x1` (94%) |
| OR | 4/4 | `x0∨x1` (84%) |
| NAND | 4/4 | `¬(x1∧x0)` (89%) |
| 3입력 다수결 | 8/8 | (게이트 8개 × 2층) |

게이트를 1개만 주면 그 게이트가 정답 논리식이 되는 수밖에 없으니, 위 표는
"정말로 그 논리를 배웠다" 는 뜻입니다.

XOR 자리에 `x0↔x1`(XNOR) 이 나온 것에 주의하세요. **여집합으로 배울 수 있습니다.**
뒤에 붙는 출력층이 부호를 뒤집으니 회로는 맞습니다 — 읽을 때 "이거 아니면 그 반대"
로 보면 됩니다.

### 처음에는 아무것도 안 합니다

갓 만든 `logic` 층은 **입력이 뭐든 정확히 0.5** 를 뱉습니다. 16가지 게이트가 서로
반대인 것끼리 쌍을 이루는데(합이 항상 1), 처음엔 16가지를 똑같이 섞으니 평균이
정확히 0.5 가 되기 때문입니다.

그래서 **조금 학습시켜야 비로소 뭔가 하기 시작합니다.** 학습 전에 출력을 찍어보고
"다 똑같은 값이 나오는데?" 싶으면 그게 정상입니다.

### 쓸 때 알아둘 것

- 들어온 값은 0~1 로 눌러서 참/거짓처럼 씁니다. 그래서 **참/거짓을 넣고 싶으면
  `±6` 처럼 크게 벌려서** 주세요. `0/1` 을 그대로 주면 `0.5 / 0.73` 이 되어
  애매해집니다.
- 로직 층을 **연달아 쌓으면** 두 번째는 다시 누르지 않습니다 (이미 0~1 이므로).
  더 복잡한 논리는 이렇게 쌓아서 만듭니다.
- 각 유닛이 볼 **입력 두 칸은 무작위로 정해지고 고정됩니다.** 연결까지 학습시키면
  경우의 수가 터지기 때문입니다. 그래서 게이트 수를 넉넉히 주는 게 좋습니다
  — 필요한 조합이 뽑힐 기회가 늘어납니다.
- 이건 **그냥 층입니다.** 보상이나 손실은 건드리지 않으니, 어떻게 학습시킬지는
  쓰는 쪽에서 정하면 됩니다 (`sl`, `save`, `jepa` 뭐든).

## jepa — 요약을 예측하기 (월드모델)

"다음에 뭐가 일어날지"를 배우게 하고 싶을 때 씁니다.

문제는, 다음 장면을 **그대로** 맞추게 시키면 예측이 애초에 불가능한 부분까지
맞춰야 한다는 것입니다. 배경에서 흔들리는 나뭇잎 같은 것들이요. 그건 무작위라
아무리 배워도 못 맞히는데, 거기에 계속 힘을 씁니다.

`jepa` 는 원본 대신 **요약**만 맞춥니다. "사람이 오른쪽으로 걸어간다" 정도의
요약에는 나뭇잎이 안 들어가니, 그걸 버리는 게 이득이 됩니다.

```python
from ml import jepa

w = jepa("world", 입력수, summary=32, actions=행동수)

손실 = w.train(지금들, 다음들, 행동들)   # 묶음으로 줍니다 (32개 이상 권장)
w.encode(관측)                           # 관측 -> 요약 (숫자 32개)
w.imagine(관측, 행동)                    # 관측 -> 다음 요약 = 미리 상상해보기
w.roll(요약, 행동)                       # 요약 -> 다음 요약 (여러 걸음 이어 붙이기)
w.save()                                 # 요약기·예측기 둘 다 저장
```

이름 하나와 입력수만 주면 요약기(관측 → 요약)와 예측기(요약 + 행동 → 다음 요약)를
알아서 만듭니다. 가중치는 `world_enc_...pth` / `world_pred_...pth` 로 저장됩니다.
`summary` 는 요약 크기, `actions` 는 행동 입력 개수(기본 0 = 행동 없는 자기지도학습),
`hidden` 은 은닉 폭입니다.

**여러 걸음 상상하기** — `imagine()` 은 관측을 받으니 한 걸음밖에 못 갑니다.
두 걸음부터는 나온 요약을 그대로 다시 넣는데, 그게 `roll()` 입니다. 월드모델로
계획을 세우는 게 이 모양입니다 (`main.py` 가 이걸 합니다).

```python
s = w.encode(관측)
for 행동 in 계획:
    s = w.roll(s, 행동)       # 실제로 움직이지 않고 머릿속에서만
```

요약기에 `attn`/`conv`/`memory` 를 넣고 싶으면 모델을 직접 만들어 묶어도 됩니다.
위 짧은 형태와 똑같이 동작합니다.

```python
요약기 = make("enc",  [입력수, 128], [vec(32)])
예측기 = make("pred", [32 + 행동수, 128], [vec(32)])
w = jepa(요약기, 예측기)        # 입력수 - 요약 크기 = 행동 개수로 계산됩니다
```

`vec(n)` 은 숫자 n개를 한 덩어리로 내는 출력입니다. `predict()`/`rl()` 은 한 칸짜리라
vec 자리에는 `None` 이 나오고, 값은 `encode()` 나 `embed(입력, 0)` 으로 꺼냅니다.

`x` 에 지금 / `y` 에 다음을 주면 월드모델이고, 같은 것의 두 조각을 주면 표현학습입니다.
라이브러리 입장에선 똑같고, 뭘 넣을지는 쓰는 쪽 마음입니다.

### 실제 차이

6칸짜리 고리 위를 좌우로 움직이는 세계입니다. 어느 칸인지는 직접 안 보여주고,
칸마다 정해진 24개 숫자에 **매번 새로 섞이는 잡음**을 얹어서만 보여줍니다.
잡음은 원래 못 맞히므로, 요약기가 그걸 버려야만 잘 하게 되는 설정입니다.

| | 정확도 (찍으면 16.7%) |
|---|---|
| 잡음 뚫고 어느 칸인지 맞히기 | **100%** |
| `imagine()` 이 진짜 다음 칸을 가리키는지 | **100%** |

### ⚠ 붕괴(collapse) — 이게 이 방식의 유일한 함정입니다

요약끼리 비교해서 배우면 요약기가 잔머리를 굴릴 수 있습니다.
**입력이 뭐든 늘 같은 값을 뱉으면 예측이 항상 맞습니다.** 손실 0, 만점.
아무것도 안 배우고 시험을 통과하는 겁니다.

`jepa(..., var=25, cov=1)` 이 그걸 막는 힘입니다. 요약값들이 서로 충분히
다르도록 강제합니다. 기본값이 켜져 있으니 보통은 신경 쓸 필요가 없지만,
**0 으로 두면 안 됩니다.** 같은 실험에서 껐을 때:

| | 요약이 퍼진 정도 | 손실 | 다음 칸 맞히기 |
|---|---|---|---|
| 켰을 때 | 0.90 | 0.96 | **100%** |
| 껐을 때 | **0.0004** | **0.000005** | 15% (찍는 수준) |

껐을 때가 손실은 20만 배 낮은데 실제 능력은 찍는 것과 같습니다.
**손실만 보면 훨씬 잘 되는 것처럼 보입니다.** 이게 이 함정이 위험한 이유입니다.

이 계산만 **묶음 전체를 한꺼번에** 봐야 합니다 ("이 묶음 안에서 서로 다른가"가
질문이라서요). 그래서 묶음이 2개 미만이면 아예 꺼집니다.

### 기존 학습과 섞어 쓰기

요약기에 출력을 더 붙이면 신경망 몸통 하나를 `jepa` 와 일반 학습이 같이 씁니다.
첫 출력만 `vec` 이면 됩니다.

```python
w = jepa("world", 입력수, actions=2, outputs=[["왼쪽", "오른쪽"]])
enc = w.encoder

w.train(지금들, 다음들, 행동들)             # 요약을 다듬습니다 (정답 필요 없음)
enc.sl(관측들, [[None, "왼쪽"], ...])       # 행동을 가르칩니다
enc.predict(관측)   # -> [None, "왼쪽"]     vec 자리는 None
w.encode(관측)      # -> 숫자 32개          요약은 여기서 꺼냅니다
```

vec 자리는 정답과 점수에서 `None` 으로 비웁니다 (숫자 하나로 표현할 수 없어서,
값을 주면 막습니다). 그냥 `w.encode()` 결과를 별개 모델의 입력으로 넘겨도 됩니다.

**효과는 문제마다 다릅니다.** 위 세계에서 정답 개수를 바꿔가며 재봤습니다.

| 정답 개수 | 정답만으로 학습 | jepa 먼저 | 차이 |
|---|---|---|---|
| 6 | 48.0% | 48.4% | +0.4%p |
| 12 | 67.2% | 69.7% | +2.4%p |
| 24 | 73.9% | 78.6% | +4.7%p |
| 60 | 85.4% | 84.6% | −0.8%p |
| 180 | 88.2% | 87.5% | −0.7%p |

정답이 적을 때만 조금 나았고, 충분하면 차이가 없거나 오히려 살짝 손해였습니다.
시드 3개 평균인데 시드별 편차가 ±5%p 라서 +4.7%p 도 확실하다고 하긴 어렵습니다.
켜면 무조건 좋아지는 것이 아니니 직접 재보고 쓰세요.

## 예전 버전에서 넘어오기

v0.1 과 v0.2 는 API 가 호환되지 않습니다. 예전 코드는 그대로 돌아가지 않습니다.
예전 버전이 필요하면 `git checkout v0.1` 로 돌아갈 수 있습니다.

### 가중치 파일 변환

```python
from ml import change

change("MyModel")     # MyModel_ml_memory.pth 를 새 포맷으로
```

원본은 `.bak` 으로 남습니다. 이미 새 포맷이면 아무것도 하지 않습니다.
예전에 출력을 여러 개 썼다면 그대로 다 보존됩니다.

### 바뀐 것

| v0.1 | v0.2 |
|---|---|
| `make("M", ["A","B"], hidden_layers=[128])` | `make("M", [입력수, 128], [["A", "B"]])` |
| `chosen = ai.rl(acts, 체력, 라운드)` | `step = ai.rl([체력, 라운드])` |
| `ai.reward(+1)` — 여기서 학습 | `ai.save(ai.reward(step, +1))` — 여기서 학습 |
| `with ai.episode():` | `ai.episode(steps, 점수)` |
| `ai.save()` | `ai.save(scored)` — 인자 필수 |
| `ai.step()`, `ai.last_reward()` | 없어짐 |
| `make(..., reset=True)` | 없어짐 (`resset("M")` 로 파일 삭제) |

`reward()` 는 이름이 그대로지만 **더 이상 학습하지 않습니다.** 데이터만 만듭니다.
예전 코드가 에러 없이 조용히 학습만 안 되는 상태가 되니 주의하세요.

만들어진 `ml.pyd` 가 있는 폴더에서 `import ml` 로 씁니다.

## 성능

배치 1 온라인 학습(이 라이브러리의 주 용도)에서는 파이토치보다 빠릅니다.
직접 작성한 네이티브 파이토치 코드와 같은 조건으로 비교한 결과입니다.

| 구성 | 이 라이브러리 | 네이티브 PyTorch |
|---|---|---|
| `[1, 128, 3]` | **9.0 µs** | 707 µs |
| `[64, 128, 3]` | **91 µs** | 1,093 µs |
| `[256, 512, 3]` | 1,284 µs | **1,161 µs** |

이 차이는 구조적입니다. 파이토치는 연산 하나마다 파이썬 디스패치와 텐서 할당,
자동미분 그래프 생성을 거치는데, 이 고정비가 망 크기와 무관하게 붙습니다.
작은 망에서는 그 고정비가 계산량보다 큽니다.

반대로 망이 커지면(대략 13만 파라미터 이상) 파이토치가 유리합니다.
큰 행렬곱은 수십 년 튜닝된 MKL/cuBLAS 커널을 쓰기 때문이고, 여기를 이기려고
만든 라이브러리가 아닙니다. 묶어서 학습할 수 있는 작업이면 파이토치를 쓰세요.

### 결과가 항상 똑같습니다

스레드 수를 바꿔도 **비트 단위로 같은 값**이 나옵니다. `MYML_THREADS=1` 이든 8이든
결과가 동일합니다. 병렬 처리를 할 때 각 조각이 서로 겹치지 않는 출력만 맡고
합산 순서를 보존하도록 짜여 있어서입니다 (파이토치는 이걸 보장하지 않습니다).

`tests/regression.py`, `tests/rl.py`, `tests/jepa.py` 가 매번 이걸 검사합니다.
실험을 다시 돌렸을 때 숫자가 미묘하게 달라지는 일이 없어야 하는 곳에서 쓸 만합니다.

### 그 밖에

- 설치가 `.pyd` 파일 하나입니다. 의존성도 없습니다.
- 워밍업이나 JIT 컴파일이 없습니다. 첫 호출부터 최고 속도입니다.
- 빌드에 GPU 툴체인이나 SDK 가 필요 없습니다.

### GPU (기본 꺼짐)

OpenCL 백엔드가 들어있습니다. 큰 묶음 학습에서만 이득이 있어서 기본은 꺼둡니다.
AMD gfx1035 **내장** GPU 실측입니다.

| 층 | 묶음 | CPU (12스레드) | GPU | |
|---|---|---|---|---|
| `[128,256,256]` | 64 | 1.7 ms | **1.3 ms** | GPU 1.25배 |
| `[128,256,256]` | 1024 | 19.7 ms | **15.5 ms** | GPU 1.27배 |
| `[512,1024,1024]` | 256 | 45.8 ms | **21.7 ms** | GPU 2.11배 |
| `[512,1024,1024]` | 1024 | 176.2 ms | **76.8 ms** | GPU 2.29배 |
| `[1024,2048,2048]` | 512 | 315.3 ms | **115.4 ms** | GPU 2.73배 |

**단, 위 숫자는 "학습만 연달아" 돌릴 때입니다.** 쓰는 방식에 따라 크게 달라집니다.

| 쓰는 방식 | `[512,1024,1024]` 묶음 1024 | `[128,256,256]` 묶음 256 |
|---|---|---|
| 학습만 연달아 | GPU 2.16배 | CPU 1.05배 |
| 학습 ↔ 평가 번갈아 | GPU 1.66배 | **CPU 1.57배** |
| 한 번만 학습 | **CPU 25배** | **CPU 209배** |

- **첫 호출에 약 1.3초**가 듭니다. OpenCL 이 커널을 실행 시점에 컴파일하기 때문이고,
  망 크기와 무관한 고정 비용입니다. 오래 도는 학습에서는 묻히지만 짧은 스크립트에서는
  이게 전부입니다.
- **`predict()` 를 섞으면 이득이 줄어듭니다.** 가중치를 GPU 에 남겨두는 방식이라,
  `predict()` 가 한 번 들어올 때마다 호스트로 내려받고 다음 학습에서 다시 올립니다.

배치 1 온라인 학습에는 GPU 가 아예 개입하지 않습니다 — 디스패치 비용이 계산보다
크기 때문입니다.

켜려면 `MYML_GPU=1`(강제) 또는 `MYML_GPU=auto`(문턱값), 지금 쓰고 있는지 확인하려면
`gpu_info()` 를 부르세요 (`runs` 가 0이면 안 쓰고 있는 것입니다).

기본을 안 켜는 이유는, 이득이 나는 구간이 이 라이브러리의 주 용도(작은 온라인
학습)와 어긋나는데다 외장 GPU 에서 어떨지 검증할 방법이 없어서입니다.
내장 GPU 는 CPU 와 같은 메모리를 나눠 쓰므로 위 숫자는 보수적인 쪽일 것입니다.

### 강화학습 학습 속도

`save(scored)` 는 기본적으로 부를 때마다 가중치 파일을 씁니다. 망이 커지면
이게 학습 자체보다 비쌉니다. 매 스텝 학습하는 온라인 RL 이면
`make(..., autosave=N)` 으로 N 번에 한 번만 쓰게 하고, 끝날 때 `ai.save()` 로
마무리하세요. 층 `[64,256,256]`, 묶음 크기별 실측입니다.

| 묶음 | 매번 파일 쓰기 | `autosave` 조절 | |
|---|---|---|---|
| 1개 (온라인) | 12.4 ms | **0.31 ms** | 40배 |
| 64개 | 14.8 ms | **1.45 ms** | 10배 |
| 256개 | 31.6 ms | **7.44 ms** | 4배 |

`sl()` 은 원래 파일을 쓰지 않으므로 해당 없습니다.
